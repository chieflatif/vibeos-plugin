# VibeOS 2.3.0

Status: locally qualified for release. The immutable GitHub tag and release
record provide publication identity and distribution readback.

This release updates the canonical `chieflatif/vibeos-plugin` distribution for
fresh macOS/Codex projects. It includes the six previously unpublished generic
commits through `082a011`, adopts the reusable September 13 engineering controls,
and preserves project-owned requirements, rules and customizations.

## What changed

- The profile installer adds `verify` and `recover`, binds plans to source,
  profile, output and target bytes, preserves customization as merge candidates,
  and serializes journaled install/recovery operations.
- Controlled evaluation separates protected owner tests from the candidate,
  checks exact required results and runner exits, detects drift and incomplete
  evidence, and publishes an immutable `PRE_REVIEW` result.
- Required gate phases cannot pass with no checks. Missing or skipped blocking
  checks fail; macOS timeouts terminate the gate process group without requiring
  GNU coreutils.
- Installation guidance uses a pinned release and a project-owned profile.
  Legacy Codex/bootstrap repositories point users to this canonical source.

The source adoption record contains the original contribution and adapted-file
hashes. Product-specific tests, policies, customer source, private proof archives,
and fixed machine paths are excluded. This is an adaptation of shared controls,
not a copy of a finished product harness.

## Verification

The initial generic baseline had 256 passing tests and two failing hook fixtures.
Those fixtures lacked their explicit managed-project opt-in. The correction adds
that opt-in and preserves the original assertions. The first integrated suite
passed 304 tests and 46 subtests; independent review then identified additional
installer verification gaps, which receive regression tests before publication.
After review corrections, the final integrated suite passed **311 tests and 51
subtests**, with one intentional skip preventing recursive invocation of the
pre-commit gate. Both native installed-project proofs passed again on these
corrected bytes. Default framework Ruff and strict controlled-evaluator Ruff
passed. The staged canonical pre-commit phase passed nine checks, with zero
failures and one nonblocking dependency-audit skip; no vulnerability-audit PASS
is claimed for that optional check. [Independent review](independent-review.md) records findings and closure.

The canonical manifest measures default Ruff quality over framework scripts and
function size/parameter complexity over the new controlled-evaluation package.
The latter scope is explicit: it does not certify all historical framework code
or test fixtures. The native evaluator additionally enforces Ruff E9/F/C901 with
maximum cyclomatic complexity 10 and a 300-line file limit on its protected
Python inputs. The old complexity gate printed failures without propagating
them; this release fixes that behavior rather than treating its old PASS as proof.

The separate native proof uses actual Codex sandbox execution on synthetic Python
and JavaScript projects. It exercises fresh analyze/verify/apply/verify, the
installed evaluation entrypoint, real tests, valid/invalid project inputs, denied
candidate and protected-owner writes, and repeat publication. It uses no provider
calls. [Measured native results](native-proof-summary.json) record the outcomes. The frozen automated evaluator tests emulate the launcher and are not
presented as native isolation evidence.

Measured environment: macOS, Codex 0.147.0, Python 3.14.6, Ruff 0.15.0, Node
24.3.0, Git 2.50.1 and Bash 3.2.57. Python 3.12 is the package minimum because
existing framework code uses syntax introduced in that version; the measured
Python version above is the one exercised. No Windows/Linux qualification or
installation on the user's second Mac is claimed.

## Distribution and adoption

Use [the installation guide](../INSTALLATION.md) and the immutable `v2.3.0` tag.
The existing CC BY-NC 4.0 license and copyright remain unchanged. The contribution
was supplied by the framework owner; no third-party source or runtime dependency
was added. Development checkouts may have local changes; install provenance must
identify that state separately from the Git reference and generated-byte hashes.

A successful install verifies the installed framework. A controlled-evaluation
result remains `PRE_REVIEW`; neither establishes application acceptance, deployment
authority or hostile same-user isolation. Configure each project's own required
tests and review policy. Existing Codex capabilities are detected locally.

The legacy bootstrap replacement route has a different upgrade contract. Use
the profile installer for customized installations, as described in the guide.
