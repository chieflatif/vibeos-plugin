# VibeOS 2.3.1

This patch corrects findings from an independent Claude audit of published 2.3.0
before handoff to a fresh macOS/Codex project. The 2.3.0 tag remains unchanged.
Use [the installation guide](../INSTALLATION.md) with `v2.3.1`.

## Corrections

- Default Git-hook setup preserves unrelated hooks and adds commit-message
  enforcement only when explicitly enabled with its real validator installed.
  A regression exercises setup, audit, verify and a real Git commit.
- Both legacy bootstraps refuse profile-managed targets before mutation,
  including upgrade, force and uninstall operations.
- Detected validators and profile primary checks are explicitly informational.
  Only executable manifest gates can produce gate results. Configure each
  application's required checks as real project-owned manifest rows/scripts.
- Missing required lint or complexity tools cannot produce PASS. Required gates
  fail closed; the Python complexity gate can use installed Ruff C901.
- Skipping post-install checks exits nonzero and gives the fresh-plan recovery
  route. The CLI reports its Python 3.12 prerequisite before loading the installer.
- Controlled evaluation uses a total execution deadline and forwards termination
  to active check groups. Regression tests exercise actual nested processes.
- Generated guidance refers to the project owner. Installation and evaluation
  docs explain customization drift, cleanup limits and strict admission rules.

## Audit and validation

Claude Fable 5.1 (`claude-fable-5-1`, first-party Claude Code) independently read
an exact archive of published commit `c3651b2226a54e20e9b5d4addc694100312536c7`.
Its static audit returned PASS_WITH_LIMITS with one P1 and five P2 findings.
The P1 was reproduced on unchanged 2.3.0: hook setup exited 0, surface audit 1,
verify 2, and a real commit 1. Primary execution evidence and the later targeted
Claude review are separate; Claude's read-only reviews do not claim test execution.

The targeted Claude review returned **PASS_WITH_LIMITS** and closed all six
material findings. All ten release gates completed: nine PASS, zero FAIL, and
one declared nonblocking dependency-audit SKIP. The full pytest suite passed
inside the tests gate. Final missing-tool regressions passed seven tests; the
new parse-error compatibility correction also passed with macOS Python 3.9.6.
The installer still requires Python 3.12 or newer. Actual native deadline and
direct-SIGTERM proofs both stopped the adapter and grandchild without admission
or candidate changes.
See [the finding resolution record](claude-audit-resolution.md).

## Operating limits

Installation verification certifies the installed framework, not application
acceptance. Profile command strings do not execute automatically. Controlled
results remain PRE_REVIEW pending the project owner's independent acceptance.

The transaction lock file persists; interruptions outside the journaled windows
can leave temporary files or backups requiring inspection. Mode changes do not
prune retired surfaces automatically. These are documented low-priority limits,
not claims of complete cleanup or automatic downgrade support.

The measured target is macOS/Codex. Native proof uses synthetic Python and
JavaScript projects; no installation on the user's second Mac or Windows/Linux
qualification is claimed. The optional dependency audit may SKIP and does not
constitute a vulnerability-audit PASS.
