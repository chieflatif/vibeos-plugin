# VibeOS 2.3.2

This patch closes an accepted-state custody gap found while repairing the Joan
engineering repository. VibeOS already isolated worktrees and required PR-based
merges, but it did not prevent an accepted product baseline from remaining only
in a topic branch, archive or temporary worktree while an older default branch
continued to appear canonical.

## Correction

- A new `.vibeos/canonical-closeout.json` binds either exact accepted product
  source or an evidence-only artifact.
- `validate-canonical-closeout.py` clones the declared remote default branch
  afresh and fails unless the pushed manifest, front doors and accepted identity
  are recoverable there.
- Product-source acceptance requires the exact accepted commit and tree to be
  reachable from the remote default branch.
- Evidence-only acceptance requires an exact remote artifact and SHA-256 digest;
  it never silently promotes archived source.
- Build and worktree guidance now keep a milestone at `Awaiting Canonical
  Promotion` until this post-acceptance close passes.
- A historical release amendment incorrectly named `WO-132` was renamed so it
  no longer collides with the planned WO-132 Apply + Preserve + Rollback Engine
  or breaks the work-order index generator.

## Verification

- Exact false-green reproduction: accepted source on a pushed topic branch but
  absent from remote `main` fails.
- Promotion of that exact commit to remote `main` passes.
- Evidence-only artifact, bad digest, unpushed manifest and missing front-door
  cases are covered by planted regressions.
- Profile installation proves the validator is delivered to a target project.
- Full suite: 337 tests and 59 subtests passed before the version-only release
  update; the final release suite and pre-commit result are recorded in GitHub CI.

This release changes engineering closeout governance only. It does not accept an
application, deploy software, select a provider or alter project product logic.
