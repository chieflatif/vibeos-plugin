# VibeOS 2.4.0

Publication gate: the closed companion receipt required by the audit state machine,
protected-main merge, immutable tag and published-source readback.

This additive release gives Codex-led engineering projects a real, efficient
cross-identity audit lane. The module is disabled by default and changes no existing
project until its profile explicitly opts in.

## What changed

- `claude-companion-audit.py` sends one frozen review packet to exact first-party
  `claude-fable-5-1` with restricted, tool-free, non-persistent CLI execution and
  bounded spend/turns.
- The full receipt binds work-order and acceptance bytes, base/candidate commits,
  review snapshot, scope, diff, evidence, prompt, provider output, CLI provenance and
  the exact implementation commit/tree that passed deterministic checks.
- Corrections receive a targeted verification covering every original finding ID.
  Changed acceptance contracts, corrections outside the original review scope and
  new material blockers require a new full audit.
- The independent-audit close gate validates the registered receipt against current
  project bytes and fails on missing, open, drifted or unproved review state.
- Profile installation is default-off and adds the CLI, skill on Codex/Claude/Cursor,
  and blocking `wo_exit` gate only when explicitly enabled.
- The existing local-model lane remains advisory intake only and is not promoted to
  implementation, audit or acceptance work.

## Automated verification

The exact focused and full-suite commands and current counts are recorded once in
`docs/evidence/WO-157/automated-tests.md`; this release note does not duplicate
mutable counts.
- The first sandboxed full run correctly exposed seven existing loopback-fixture
  permission failures; the exact suite passed when rerun with localhost test-server
  permission. No product network service was contacted.
- Ruff passed for the new audit CLI, installer and relevant tests; the audit shell
  validator passed Bash syntax validation.

The fake-CLI tests prove packet, command, schema, receipt, correction and refusal
contracts. They are not evidence of a real Claude call. Real provider receipts, reports
and raw results remain local integrity artifacts under `.vibeos/audit-reports/`; the
committed WO-157 evidence records audit IDs and outcomes but is not standalone proof of
the provider call. Publication requires the locally registered receipt to validate and
its state machine to report no further audit action.

## Operating limits

The module requires a backend process that can prove a logged-in first-party Claude
Code account. VibeOS does not install, export or copy credentials. Opt-in authorizes
bounded source/evidence review for that project only; it does not authorize deployment,
product acceptance or unrelated provider use.

The model has no tools and reviews only the supplied packet. Deterministic tests and
gates remain separate execution evidence. A successful receipt proves the configured
audit boundary, not hostile same-user isolation or application acceptance.

The plugin's own one-time release uses the validator and exact receipt/report check as
a manual WO-157 publication checklist because the not-yet-published version cannot
install its gate into itself first. Projects that opt into the published module receive
the blocking `wo_exit` enforcement automatically.
