# VibeOS 2.4.1

Publication gate: independent source review, passing release checks, protected-main
merge and exact published-tree readback. Project adoption follows package canary.

This update simplifies the optional independent-review lane while keeping review
evidence honest. It does not enable the module in existing projects automatically.

- Generated Codex roles no longer pin old GPT models. The parent selects an
  available model and reasoning effort for each assignment, with Luna a first-choice
  candidate for bounded work and stronger models selected when the task warrants it.
- One companion review replaces overlapping generic auditor dispatch. Additional
  specialists need a named coverage gap.
- New receipts support targeted correction chains, including newly found local
  blockers. Critical/high findings and unmet acceptance requirements block; minor
  advice needs an explicit disposition. Old receipts retain their old semantics.
- Reviewed files and evidence remain bound, while unrelated workspace work and
  prospective execution-limit changes no longer invalidate completed review.
- An enabled gate fails if its change identity or structured review evidence is
  absent. Valid structured evidence is not rechecked with legacy prose heuristics.
- Operational Claude failure is surfaced for the user's decision. The supported
  fallback requires explicit recorded authorization, then invokes a fresh Codex
  context requesting the implementing model. It never invents Claude provenance.

The fallback records CLI-requested model selection; this runtime does not expose
provider-observed serving-model identity in its JSONL stream. Its read-only sandbox
request and rejection of tool events are not a claim of tool-free execution or
hostile same-user isolation. Approval records preserve user direction; they are not
cryptographic proof of who wrote a local file.

No local-model expansion, JEV integration, Foundry provisioning or project-wide
retrofit is part of this source patch. Testing, release and each project's adoption
are separate claims recorded in the existing work record.
